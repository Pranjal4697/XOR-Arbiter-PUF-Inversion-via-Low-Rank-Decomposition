# XOR Arbiter PUF Inversion via Low-Rank Decomposition

An efficient mathematical approach for recovering the underlying **non-negative delay parameters** of an XOR Arbiter Physical Unclonable Function (PUF) by exploiting its **Kronecker-product structure and low-rank decomposition**.

> **Course:** CS771 — Machine Learning  
> **Institution:** Indian Institute of Technology Kanpur  
> **Date:** November 2025

## Overview

This project addresses the inverse problem of recovering the underlying parameters of an **XOR Arbiter PUF** from its high-dimensional model representation.

The given XOR PUF model contains **1089 dimensions**, while the underlying physical system is parameterized by **256 non-negative delay values**.

Instead of treating the inversion as a generic constrained optimization problem, the approach exploits the mathematical structure of the XOR Arbiter PUF to decompose the high-dimensional model into its constituent PUF components and reconstruct the underlying delay parameters.

The project focuses on:

- Kronecker-product structure in XOR Arbiter PUFs
- Low-rank matrix decomposition
- Singular Value Decomposition (SVD)
- Constituent PUF parameter recovery
- Non-negative delay reconstruction
- Efficient vectorized numerical computation

## Problem Formulation

The goal is to invert an XOR Arbiter PUF model and recover the underlying physical delay parameters.

The high-dimensional XOR PUF representation contains structured information generated by its constituent Arbiter PUF models. By exploiting this structure, the inversion problem can be transformed into a sequence of matrix decomposition and parameter reconstruction steps.


## Methodology

### Kronecker-Product Structure

The XOR Arbiter PUF representation exhibits a **Kronecker-product structure** resulting from its constituent PUF models.

This structure is exploited to avoid treating the 1089-dimensional model as an unstructured parameter-estimation problem.

By identifying the underlying structure, the high-dimensional representation can be decomposed into the constituent components required for inversion.

### Low-Rank Decomposition

The structured representation is reshaped into a matrix form that exposes its low-rank structure.

This allows the constituent PUF components to be recovered through matrix factorization rather than solving the complete inverse problem directly.

### Singular Value Decomposition

**Singular Value Decomposition (SVD)** is used to decompose the structured matrix and recover the underlying constituent PUF parameters.

For a matrix $A$, the decomposition is:

$$
A = U\Sigma V^T
$$

The dominant singular components capture the low-rank structure of the XOR PUF representation and are used to recover the constituent PUF models.

### Non-Negative Delay Reconstruction

After recovering the constituent PUF parameters, the underlying physical delay values are reconstructed.

The recovered delays are constrained to be **non-negative**, matching the physical interpretation of the model.

Rather than relying on generic constrained optimization, the project uses the recovered PUF structure to directly reconstruct the delay parameters.

## Why Low-Rank Decomposition?

A direct inversion approach would treat the high-dimensional XOR PUF representation as a generic parameter estimation problem.

The proposed approach instead exploits known structure in the model:

- **Kronecker-product structure** exposes the constituent PUF components.
- **Low-rank decomposition** reduces the effective complexity of the inversion.
- **SVD** provides a numerically efficient mechanism for recovering the constituent parameters.
- Direct reconstruction avoids the need for generic constrained optimization.

This turns the inversion problem into a structured sequence of algebraic operations.

## Computational Implementation

The complete solver is implemented using **NumPy vectorization**.

Vectorized operations are used for:

- Matrix construction
- Kronecker-product operations
- SVD-based decomposition
- Parameter extraction
- Non-negative delay reconstruction

The implementation avoids unnecessary Python-level loops and relies on optimized numerical linear-algebra operations.
